# 景区导览服务 AI 数字人系统总体设计文档

## 1. 项目概述

### 1.1 项目名称

景区导览服务 AI 数字人系统

### 1.2 项目背景

随着文旅行业数字化转型推进，传统景区导览服务普遍存在讲解资源有限、游客咨询响应不及时、路线规划缺乏个性化、景区运营数据利用不足等问题。游客希望在游览过程中获得更加自然、实时、个性化的服务体验，景区管理方也需要通过数字化手段提升服务效率、降低人工成本、优化运营决策。

本项目拟构建一个面向景区游客和景区管理人员的 AI 数字人导览服务平台，综合运用大语言模型、知识库检索、语音交互、路线推荐、数据分析等技术，为游客提供智能问答、景点讲解、路线推荐、文化科普、服务咨询等能力，为景区管理方提供知识库维护、游客咨询分析、热门问题统计、服务质量评估等能力。

### 1.3 建设目标

系统建设目标包括：

1. 构建可交互的景区 AI 数字人，为游客提供自然语言导览服务。
2. 建立景区知识库，实现景点介绍、历史文化、交通餐饮、门票开放时间等信息的准确问答。
3. 支持个性化路线推荐，根据游客偏好、游览时间和景点热度生成游览方案。
4. 支持语音播报和拟人化讲解，提升游客沉浸式体验。
5. 建立景区运营管理后台，实现知识库管理、问答记录分析、游客需求统计等功能。
6. 形成完整可演示、可部署、可扩展的比赛作品。

### 1.4 设计原则

1. 实用性：围绕真实景区服务场景设计功能，保证系统可演示、可使用。
2. 易用性：游客端操作简单，支持自然语言提问和推荐结果可视化展示。
3. 可扩展性：知识库、景点数据、推荐策略和模型服务均支持扩展。
4. 稳定性：核心功能优先采用成熟技术栈实现，降低比赛开发风险。
5. 可解释性：AI 回答尽量引用知识来源，路线推荐给出推荐理由。
6. 安全性：后台管理、接口访问和数据存储具备基础权限控制。

## 2. 需求分析

### 2.1 用户角色

系统主要包含三类用户角色：

| 用户角色 | 使用目标 | 核心功能 |
| --- | --- | --- |
| 游客 | 获取导览、咨询、路线推荐 | AI 问答、景点讲解、路线推荐、语音播报 |
| 景区管理员 | 维护景区资料和查看运营数据 | 景点管理、知识库管理、问答记录、数据看板 |
| 系统管理员 | 维护系统账号和基础配置 | 用户管理、权限管理、模型配置、系统配置 |

### 2.2 游客端需求

游客端面向普通游客，重点突出交互体验和导览价值。

#### 2.2.1 AI 数字人导览

1. 支持游客通过文字输入向数字人提问。
2. 支持常见问题快捷入口，例如门票价格、开放时间、停车位置、必看景点等。
3. 支持数字人以拟人化语气回答游客问题。
4. 支持回答内容展示关联景点、图片、推荐路线等补充信息。

#### 2.2.2 景区知识问答

1. 支持景点介绍、历史文化、游览建议、服务设施等知识问答。
2. 支持基于知识库检索增强生成，降低模型胡编风险。
3. 支持无法回答时提示游客联系人工服务或查看景区公告。

#### 2.2.3 个性化路线推荐

1. 支持根据游览时长推荐路线，例如 1 小时、半日、一日路线。
2. 支持根据偏好推荐路线，例如亲子游、历史文化、拍照打卡、轻松休闲。
3. 支持展示路线包含景点顺序、预计耗时、推荐理由。
4. 支持游客对路线进行收藏或重新生成。

#### 2.2.4 景点详情浏览

1. 支持查看景点名称、简介、图片、开放时间、推荐指数等信息。
2. 支持查看景点讲解词。
3. 支持一键向 AI 提问该景点相关问题。

#### 2.2.5 语音播报

1. 支持将数字人回答内容转换为语音播放。
2. 支持景点讲解词语音播放。
3. 后续可扩展语音输入能力。

### 2.3 管理端需求

管理端面向景区工作人员，重点突出数据维护和运营分析。

#### 2.3.1 景点管理

1. 支持新增、编辑、删除景点信息。
2. 支持维护景点图片、标签、开放时间、推荐指数、预计游览时长。
3. 支持景点启用和停用。

#### 2.3.2 知识库管理

1. 支持维护景区公告、景点知识、服务说明、历史文化资料。
2. 支持知识内容分段入库。
3. 支持知识库检索测试。
4. 支持知识内容更新后重新构建索引。

#### 2.3.3 问答记录管理

1. 支持查看游客问题和 AI 回答记录。
2. 支持统计高频问题。
3. 支持筛选无法回答或低置信度问题，用于完善知识库。

#### 2.3.4 数据看板

1. 展示游客咨询次数、热门问题、热门景点、路线推荐次数等指标。
2. 展示游客偏好分布，例如亲子、文化、拍照、休闲等。
3. 展示系统服务趋势，辅助景区运营优化。

### 2.4 非功能需求

| 需求类型 | 说明 |
| --- | --- |
| 性能需求 | 普通问答接口响应尽量控制在 3 至 8 秒内 |
| 可用性需求 | 页面操作清晰，核心功能可在浏览器直接访问 |
| 可维护性需求 | 前后端分层清晰，核心业务模块独立封装 |
| 可扩展性需求 | 支持替换大模型、向量库、语音服务和推荐策略 |
| 安全性需求 | 管理端需要登录鉴权，接口需要基础权限校验 |
| 可演示性需求 | 支持本地部署和完整演示流程 |

## 3. 总体架构设计

### 3.1 系统架构

系统采用前后端分离架构，整体分为游客端、管理端、后端服务、AI 服务层和数据存储层。

```text
游客端 Web 页面
    │
    ├── AI 数字人交互
    ├── 景点浏览
    ├── 路线推荐
    └── 语音播报

管理端 Web 页面
    │
    ├── 景点管理
    ├── 知识库管理
    ├── 问答记录
    └── 数据看板

后端 API 服务
    │
    ├── 用户与权限模块
    ├── 景点数据模块
    ├── 智能问答模块
    ├── 路线推荐模块
    ├── 运营统计模块
    └── 文件资源模块

AI 服务层
    │
    ├── 大语言模型服务
    ├── RAG 知识库检索
    ├── 文本向量化服务
    └── 语音合成服务

数据存储层
    │
    ├── 关系型数据库
    ├── 向量数据库
    └── 静态资源存储
```

### 3.2 功能架构

系统功能模块划分如下：

| 一级模块 | 二级功能 | 说明 |
| --- | --- | --- |
| 游客端 | AI 问答 | 游客与数字人进行自然语言问答 |
| 游客端 | 景点导览 | 展示景点信息、讲解词和推荐指数 |
| 游客端 | 路线推荐 | 根据时长和偏好生成游览路线 |
| 游客端 | 语音播报 | 播放问答内容和景点讲解内容 |
| 管理端 | 景点管理 | 维护景区景点基础数据 |
| 管理端 | 知识库管理 | 维护 AI 问答知识来源 |
| 管理端 | 问答分析 | 查看游客问题和回答效果 |
| 管理端 | 数据看板 | 展示运营统计和游客需求分析 |
| 后端服务 | AI 编排 | 管理问题改写、检索、生成、记录流程 |
| 后端服务 | 推荐算法 | 生成个性化游览路线 |

### 3.3 技术架构

当前可运行版本技术架构如下：

| 层级 | 推荐技术 | 说明 |
| --- | --- | --- |
| 前端 | Vue 3、TypeScript、Vite | 实现游客端、管理端和数据看板 |
| 后端 | Python 标准库 `ThreadingHTTPServer` | 实现 REST API、AI 编排和静态资源服务 |
| 数据库 | SQLite | 比赛阶段优先 SQLite，部署简单 |
| 知识检索 | SQLite 文档 + 关键词评分 | 当前用于 RAG 检索，后续可升级向量库 |
| 大模型 | DashScope `qwen3-vl-plus` OpenAI 兼容 API | 用于文字问答、图片识别和导览讲解 |
| 语音交互 | 浏览器 SpeechRecognition / SpeechSynthesis | 比赛阶段优先浏览器内置方案 |
| 部署 | 本地运行 | 方便演示和提交 |

后续工程化升级可考虑 FastAPI、向量数据库、ParaTTS、Whisper 和 Live2D/Three.js 数字人形象。

## 4. 核心业务流程

### 4.1 AI 问答流程

```text
游客输入问题
    │
后端接收问题并记录会话
    │
问题预处理与意图识别
    │
检索景区知识库相关内容
    │
构造提示词并调用大语言模型
    │
生成回答和关联推荐内容
    │
保存问答记录
    │
前端展示数字人回答
```

### 4.2 路线推荐流程

```text
游客选择游览时长和偏好
    │
后端读取景点数据
    │
根据标签、热度、距离、耗时进行筛选
    │
生成候选路线
    │
调用模型生成自然语言推荐理由
    │
前端展示路线卡片和景点顺序
```

### 4.3 知识库更新流程

```text
管理员新增或修改知识内容
    │
后端保存知识原文
    │
系统对知识进行分段处理
    │
调用向量化模型生成文本向量
    │
写入向量数据库
    │
后续问答自动使用最新知识
```

### 4.4 运营分析流程

```text
游客产生问答和路线推荐记录
    │
后端写入日志数据
    │
统计模块按问题、景点、偏好聚合
    │
管理端数据看板展示统计结果
    │
管理员根据高频问题完善知识库
```

## 6. 界面设计概览

### 6.1 游客端页面

1. 首页：展示数字人入口、热门景点、推荐路线入口。
2. AI 导览页：展示数字人形象、聊天窗口、快捷问题和语音播报。
3. 景点详情页：展示景点图文介绍、讲解词和相关问答入口。
4. 路线推荐页：选择游览时长、游客偏好，展示推荐路线。

### 6.2 管理端页面

1. 登录页：管理员登录系统。
2. 数据看板页：展示核心运营指标和图表。
3. 景点管理页：维护景点基础资料。
4. 知识库管理页：维护景区问答知识。
5. 问答记录页：查看游客咨询记录和高频问题。

## 7. 创新点设计

### 7.1 RAG 景区知识增强问答

系统不直接依赖大模型记忆回答，而是先检索景区知识库，再结合检索结果生成回答，提高回答准确性和可控性。

### 7.2 个性化路线推荐

系统根据游客游览时长、兴趣偏好、景点标签、景点热度和预计耗时自动生成路线，并给出可理解的推荐理由。

### 7.3 拟人化 AI 数字人讲解

通过数字人形象、自然语言回答和语音播报，使导览服务从传统图文说明升级为互动式讲解。

### 7.4 问答数据反哺知识库

系统对游客高频问题和无法回答问题进行统计，辅助景区管理员持续完善知识库。

### 7.5 游客偏好运营分析

通过路线推荐和问答记录分析游客需求，为景区运营、活动策划和服务优化提供数据支持。

## 10. 总结

景区导览服务 AI 数字人系统以游客智能导览和景区数字化运营为核心，能够较好体现 AI 技术在文旅行业的实际应用价值。系统功能边界清晰，技术实现可控，演示效果直观，适合作为软件杯比赛项目进行开发和展示。
