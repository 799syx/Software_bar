# 景区导览服务 AI 数字人系统部署与使用手册

## 1. 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10/11、macOS 或 Linux |
| Python | 3.10 及以上 |
| 浏览器 | Chrome、Edge 或其他现代浏览器 |
| 大模型服务 | 阿里云百炼 DashScope API，推荐 `qwen3-vl-plus` |
| 第三方依赖 | 项目源码无 Python 第三方依赖 |

语音播报演示版使用浏览器 Web Speech API。语音输入演示版依赖浏览器 `SpeechRecognition` 能力，Chrome 和 Edge 的支持较好。正式方案可扩展 Whisper/faster-whisper 语音识别和 ParaTTS 语音合成。

## 2. 配置多模态大模型 API

本项目明确使用至少 1 个多模态大模型作为核心 AI 能力。默认推荐：

| 项目 | 配置 |
| --- | --- |
| 服务商 | 阿里云百炼 / DashScope |
| 模型 | `qwen3-vl-plus` |
| 备用低延迟模型 | `qwen3-vl-flash` |
| 接口模式 | OpenAI 兼容接口 |
| Base URL | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| Key 环境变量 | `DASHSCOPE_API_KEY` |

复制配置文件：

```bash
copy .env.example .env
```

填写 `.env`：

```text
SCENIC_LLM_ENABLED=true
SCENIC_LLM_PROVIDER=dashscope
SCENIC_LLM_MODEL=qwen3-vl-plus
SCENIC_LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
DASHSCOPE_API_KEY=sk-your-dashscope-api-key
SCENIC_LLM_TEMPERATURE=0.35
SCENIC_LLM_MAX_TOKENS=700
SCENIC_LLM_TIMEOUT=5
SCENIC_VISION_MODEL=qwen3-vl-plus
SCENIC_ADMIN_TOKEN=
SCENIC_CORS_ORIGINS=http://127.0.0.1:5173,http://localhost:5173,http://127.0.0.1:8000
```

如果演示现场更关注速度，可把模型改成：

```text
SCENIC_LLM_MODEL=qwen3-vl-flash
SCENIC_VISION_MODEL=qwen3-vl-flash
```

### 2.1 配置豆包语音合成

为提升数字人自然度，推荐配置豆包/火山引擎语音合成。前端不会直接保存 Token，所有请求由后端 `/api/tts/synthesize` 代理。

```text
DOUBAO_TTS_ENABLED=true
DOUBAO_TTS_APP_ID=your-volcengine-app-id
DOUBAO_TTS_ACCESS_TOKEN=your-volcengine-access-token
DOUBAO_TTS_CLUSTER=volcano_tts
DOUBAO_TTS_VOICE_TYPE=BV700_streaming
DOUBAO_TTS_TIMEOUT=8
```

未配置豆包语音时，系统会自动回退到浏览器自然中文语音，不影响问答演示。

### 2.2 配置高德地图底图

高德底图是前端 Web JS API 能力，不配置时系统会自动使用内置景区示意图。若需要启用高德底图，在项目根目录 `.env` 中取消注释并填写：

```text
VITE_AMAP_KEY=your-amap-web-js-key
VITE_AMAP_SECURITY_CODE=your-amap-security-code
```

`VITE_` 变量是前端编译时变量，修改后必须重启 Vue 前端服务。若使用 `start_demo.bat`，关闭前端窗口后重新运行脚本；若手动运行，则在 `frontend-vue` 目录重新执行 `npm run dev`。

### 2.3 配置 LiveTalking 实时数字人

项目已接入相邻目录 `..\portable_livetalking` 中训练好的 LiveTalking 数字人。默认配置为：

```text
VITE_LIVETALKING_ENABLED=true
VITE_LIVETALKING_BASE=http://127.0.0.1:8010
VITE_LIVETALKING_AVATAR=test1
VITE_LIVETALKING_TTS_MODE=edgetts
VITE_LIVETALKING_VOICE=zh-CN-YunyangNeural
```

`start_demo.bat` 会同步启动 LiveTalking 服务。浏览器里的数字人面板会优先使用 WebRTC 实时视频和 `/human` 文本驱动接口；如果服务未启动或连接失败，会自动回退到原静态头像和语音播报链路。若要使用 `test2`，同时修改 `.env` 的 `VITE_LIVETALKING_AVATAR`，并在 cmd 中执行 `set LIVETALKING_AVATAR=test2 && start_demo.bat`。

DeepSeek 等文本模型可以作为文字问答备用，但不能证明图片识别和多模态导览能力。若使用其他服务，只要它支持 OpenAI 兼容 `/chat/completions` 且能接收 `image_url` 输入，就可以配置为：

```text
SCENIC_LLM_PROVIDER=custom
SCENIC_LLM_MODEL=your-vision-language-model
SCENIC_LLM_BASE_URL=http://your-host:port/v1
SCENIC_LLM_API_KEY=your-api-key-if-needed
SCENIC_VISION_MODEL=your-vision-language-model
```

## 3. 启动服务

在项目根目录执行：

```bash
python backend/app.py
```

如果当前终端提示找不到 `python`，可使用仓库中的启动脚本：

```bat
run_server.bat
```

脚本会优先使用 PATH 中的 Python；如果找不到，会尝试使用本机 Anaconda 路径 `E:\DC\python.exe`，并临时补齐 `E:\DC\Library\bin` 等 DLL 路径。

启动后访问：

```text
http://127.0.0.1:8000
```

游客手机和景区触屏终端访问：

```text
http://127.0.0.1:8000/mobile/
```

局域网演示时，把 `127.0.0.1` 换成后端服务器在景区 Wi-Fi 内的 IP 地址。

服务启动时会自动初始化 SQLite 数据库：

```text
backend/data/scenic_guide.db
```

如需恢复初始演示数据，可停止服务后删除该数据库文件，再重新启动。

## 4. 自建景区知识库与准确率

系统启动时会优先读取 `示范景区公开资料包` 中的灵山胜境资料，生成景点资料、服务信息、交通票务、路线推荐、安全须知和数字人讲解风格。若资料包不可用，后端也会使用灵山胜境备用数据，管理端可继续新增和编辑知识文档。

事实性问答准确率评测建议以本地知识库和 `docs/标准测试集.md` 为标准答案来源。比赛前至少准备 30-50 条测试问题，覆盖：

1. 开放时间、票务政策、停车位置、服务中心。
2. 各景点位置、开放时间、建议游览时长、讲解重点。
3. 亲子游、历史文化、自然风光、拍照打卡等路线推荐。
4. 湖区、观景台、步道等安全提醒。
5. 无障碍设施、母婴室、卫生间、出口、应急求助等现场服务。

目标：事实性问答通过率不低于 90%。如果测试中出现错误或低置信度回答，应先补充知识库，再重新测试。

## 5. 游客端使用

1. 进入首页后可直接在 AI 导览问答区输入问题。
2. 点击快捷问题可演示开放时间、亲子路线、拍照打卡、停车等场景。
3. 点击“语音”可尝试语音输入，识别结果会先写入输入框，游客确认后再发送。
4. 点击“播放问候”或开启自动播报，可听到数字人中文讲解，讲解中会显示口型/音量动效。
5. 回答下方展示意图、置信度、满意度反馈和回答来源。
6. 上传景区照片可调用 Qwen3-VL 生成图片识别与导览讲解。
7. 点击“定位”可根据 GPS 推荐附近景点。
8. 在热门景点或路线区域选择景点，可生成对应景点讲解。
9. 在游览路线区选择时长和偏好，点击“生成路线”查看推荐顺序和理由。

## 6. 管理端使用

管理端在同一页面的“管理端”区域。本地演示默认不需要填写管理令牌；如果正式部署需要保护管理接口，可在 `.env` 中设置 `SCENIC_ADMIN_TOKEN` 为强随机字符串，并把 `SCENIC_CORS_ORIGINS` 改成真实前端域名。

### 6.1 景点管理

支持新增、编辑和停用景点。景点字段包括名称、标签、开放时间、位置、建议时长、热度、图片路径、简介和讲解词。启用状态的景点会出现在游客端、路线推荐和附近景点推荐中。

### 6.2 知识库管理

支持新增、编辑、删除和启停知识文档。启用状态的知识会参与问答检索。建议按“服务信息、景点讲解、路线推荐、安全服务、数字人配置”等分类维护。

### 6.3 数字人配置

支持调整数字人名称、身份、讲解风格、服装设定、语音标识、主色和开场问候。保存后游客端会同步更新。

## 7. 数据大屏

数据大屏展示：

1. 今日服务、本周服务、问答次数、路线推荐次数。
2. 知识条目、启用景点、低置信问答和平均满意度。
3. 热门景点、高频问题、游客偏好、情感趋势、满意度趋势。
4. 基于问答和反馈生成的运营服务建议。

## 8. 自然度与延迟方案

1. 2D 数字人驱动：当前演示版使用原创小僧童 PNG 形象，结合 CSS 状态动效表现呼吸、聆听、思考、讲解和异常提示。
2. 口型同步：讲解状态使用音量条和发光提示表达播报中；正式方案可用 TTS 音素或精确 viseme 时间戳增强。
3. 语音合成：演示版优先使用豆包/火山引擎 TTS；未配置时回退 Web Speech API 的自然中文语音。
4. 语音识别：演示版使用浏览器 SpeechRecognition；正式方案可接入 Whisper 或 faster-whisper。
5. 表情配合：当前根据问答状态切换待机、聆听、思考、讲解和异常提示；正式方案可接入 Live2D、SadTalker、MuseTalk 或其他 2D 数字人 SDK。
6. 响应延迟：语音问答目标控制在 5 秒内。常见问题优先走本地知识库和规则兜底；复杂问题调用 API，超时自动降级。
7. 稳定性：所有 API 入口包含异常处理，大模型失败不会导致系统崩溃。

## 9. GPS 弱信号方案

1. GPS 正常：根据游客坐标返回最近景点。
2. 用户拒绝授权：提示游客手动描述所在区域。
3. 室内或弱信号：提示前往开阔处，或上传现场照片由多模态模型辅助判断位置。
4. 定位超时：提示检查网络或手动选择位置。
5. 精度大于 50 米：回答中标注“仅供参考”。

## 10. 常见问题

### 10.1 端口被占用

默认端口为 `8000`。如端口被占用，可在 `backend/app.py` 中修改 `PORT` 常量后重新启动。

### 10.2 语音输入不可用

部分浏览器或安全策略可能禁用语音识别。此时文本问答和语音播报仍可正常使用。

### 10.3 页面数据异常

停止服务，删除 `backend/data/scenic_guide.db`，重新启动即可重建示例数据。

如果只想清理生成物，可在项目根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/clean_workspace.ps1
```

如需同时清理构建产物或本地数据库，可分别加 `-Dist`、`-Database`。数据库会在后端下次启动时重建。

### 10.4 多模态图片讲解不可用

检查：

1. `.env` 中是否填写 `DASHSCOPE_API_KEY`。
2. `SCENIC_LLM_PROVIDER` 是否为 `dashscope`。
3. `SCENIC_VISION_MODEL` 是否为 `qwen3-vl-plus`、`qwen3-vl-flash` 或其他支持图像输入的模型。
4. 网络是否能访问 DashScope API。

## 11. 后续部署建议

比赛后可将当前标准库后端升级为 FastAPI，并把轻量混合检索升级为向量数据库。语音技术可继续扩展 Whisper/ParaTTS，数字人形象可接入 Live2D、SadTalker、MuseTalk 或其他 2D 数字人 SDK。当前数据表和接口命名已经为这些升级预留了边界。

移动端、景区终端和无公网部署细节见 `docs/移动端与离线大模型方案.md`。
