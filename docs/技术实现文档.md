# 景区导览服务 AI 数字人系统技术实现文档

## 1. 当前技术栈

| 模块 | 当前实现 | 说明 |
| --- | --- | --- |
| 前端 | Vue 3 + TypeScript + Vite | `frontend-vue` 是唯一主前端，包含游客端和管理端 |
| 后端 | Python 标准库 `ThreadingHTTPServer` | 无 pip 依赖，提供 REST API 和静态资源服务 |
| 数据库 | SQLite | 保存景点、知识库、问答、路线、反馈和数字人配置 |
| 核心多模态大模型 | DashScope `qwen3-vl-plus` API | OpenAI 兼容接口，用于文字问答和图片识别讲解 |
| RAG 检索 | SQLite 文档 + 关键词评分 | 演示版稳定可控，后续可升级向量检索 |
| 语音输入 | 浏览器 `SpeechRecognition` | Chrome/Edge 支持较好 |
| 语音合成 | 豆包/火山引擎 TTS + 浏览器自然中文语音兜底 | 后端代理豆包接口，避免 Token 暴露到浏览器 |
| 数字人驱动 | Vue 组件 + 原创 2D 位图形象 | 结合状态动效表现待命、聆听、思考、讲解和异常 |
| GPS | 浏览器 `navigator.geolocation` + Haversine | 推荐附近景点，并处理弱信号场景 |

## 3. 后端设计

后端集中在 `backend/app.py`，按职责划分为：

| 区域 | 职责 |
| --- | --- |
| 环境配置 | 读取 `.env`，构造大模型配置 |
| 数据初始化 | 建表、补字段、写入示例景点和知识库 |
| 数据访问 | 景点、知识文档、数字人配置、问答、路线、反馈 |
| RAG 检索 | 意图识别、景点匹配、知识召回、上下文组装 |
| 大模型调用 | OpenAI 兼容 `/chat/completions` 请求 |
| 业务接口 | 问答、图片识别、路线推荐、GPS 附近景点、管理端 CRUD |
| 静态服务 | 返回前端页面和资源 |
| 安全边界 | 管理端写操作令牌校验、CORS 来源白名单、接口限流 |

### 3.1 大模型配置

默认配置：

```text
SCENIC_LLM_PROVIDER=dashscope
SCENIC_LLM_MODEL=qwen3-vl-plus
SCENIC_LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
DASHSCOPE_API_KEY=sk-your-dashscope-api-key
SCENIC_VISION_MODEL=qwen3-vl-plus
SCENIC_LLM_TIMEOUT=5
```

`LLM_PROVIDER_DEFAULTS` 已内置：

1. `dashscope`：百炼 Qwen3-VL 多模态 API。
2. `deepseek`：DeepSeek 文字模型备用。
3. `custom`：自部署或其他 OpenAI 兼容服务。

### 3.3 豆包语音配置

豆包语音由后端 `/api/tts/synthesize` 代理调用，前端只拿到音频 Data URL，不接触 Access Token。

```text
DOUBAO_TTS_ENABLED=true
DOUBAO_TTS_APP_ID=your-volcengine-app-id
DOUBAO_TTS_ACCESS_TOKEN=your-volcengine-access-token
DOUBAO_TTS_CLUSTER=volcano_tts
DOUBAO_TTS_VOICE_TYPE=BV700_streaming
DOUBAO_TTS_TIMEOUT=8
```

未配置豆包凭据时，前端自动回退浏览器自然中文语音。

### 3.2 OpenAI 兼容调用

`call_openai_compatible_llm` 负责组装：

```json
{
  "model": "qwen3-vl-plus",
  "messages": [],
  "temperature": 0.35,
  "max_tokens": 700,
  "stream": false
}
```

图片识别时，用户消息使用：

```json
[
  { "type": "text", "text": "游客问题和本地知识库上下文" },
  { "type": "image_url", "image_url": { "url": "data:image/jpeg;base64,..." } }
]
```

只要模型服务兼容该格式，即可替换为其他多模态 API。

## 4. 数据库设计

| 表 | 说明 |
| --- | --- |
| `scenic_spot` | 景点资料，包含 GPS 坐标 |
| `knowledge_document` | 景区知识文档，支持启停 |
| `persona_config` | 数字人配置 |
| `chat_record` | 问答记录、来源、意图、置信度、情绪 |
| `route_record` | 路线推荐记录 |
| `feedback_record` | 满意度反馈 |
| `behavior_visit_record` | 行为样本结构化明细，默认不保存整行原始 JSON，并截断长文本控制 SQLite 体积 |

系统启动会自动执行建表和字段补齐。若删除 `backend/data/scenic_guide.db`，重启后会恢复初始示例数据。

行为样本导入体积由环境变量控制：

```text
SCENIC_BEHAVIOR_STORE_RAW_JSON=false
SCENIC_BEHAVIOR_CONTENT_MAX_CHARS=360
```

默认配置只保留统计分析所需字段。若确实需要审计原始 Excel 行，可临时将 `SCENIC_BEHAVIOR_STORE_RAW_JSON=true` 后重新导入，但数据库体积会明显增加。

## 5. AI 问答流程

```text
游客问题
  -> 字符长度校验
  -> 意图分类
  -> 景点名称/标签匹配
  -> 知识库关键词检索
  -> 组装景点与知识上下文
  -> 调用 qwen3-vl-plus API
  -> 返回回答、来源引用、意图、置信度、关联景点
  -> 保存 chat_record
```

提示词约束：

1. 必须优先依据景区资料回答。
2. 不编造不存在的票价、活动、路线和安全承诺。
3. 未明确写“免费”时不能说免费。
4. 资料不足时明确说明暂未查询到准确资料。
5. 回答控制在适合现场语音播报的长度。

## 6. 图片识别导览流程

```text
游客上传图片
  -> 前端转为 Data URL
  -> 后端校验图片数据
  -> 压缩上下文：景点列表 + 核心知识库
  -> 调用多模态模型
  -> 返回图片识别讲解、模型名和来源引用
```

图片无法判断具体景点时，模型提示会要求说明“可能性”，并建议游客补充拍摄角度、打开定位或咨询服务中心。

## 7. 知识库检索实现

`search_knowledge` 使用关键词评分：

| 匹配方式 | 分值 |
| --- | --- |
| 整句出现在内容中 | +20 |
| 关键词出现在标题 | +8 |
| 关键词出现在分类 | +5 |
| 关键词出现在内容 | +2/次，最多 3 次 |

返回 Top-4 文档。后续可升级为：

1. 文档分段。
2. 向量化嵌入。
3. FAISS / Chroma 检索。
4. 关键词 + 向量混合召回。

## 8. 路线推荐实现

路线推荐采用规则算法：

1. 按游客偏好匹配景点标签。
2. 结合热度排序。
3. 在游览时长限制内累加景点。
4. 根据偏好生成自然语言推荐理由。
5. 保存路线记录用于数据大屏统计。

## 9. GPS 附近景点

接口：

```text
GET /api/spots/nearby?lat=&lon=&limit=
```

后端使用 Haversine 公式计算游客位置与景点坐标距离。前端处理：

1. 用户拒绝授权。
2. GPS 信号不可用。
3. 定位超时。
4. 精度大于 50 米。

## 10. 前端实现

`frontend-vue/src/App.vue` 负责游客端、导览页和管理端视图切换，并在启动时加载统一的景区状态。

`frontend-vue/src/components/MapGuideExperience.vue` 负责：

1. 景区示意图/高德底图切换、点位选择、定位和路线推荐。
2. 文本问答、流式回答、来源引用和满意度反馈。
3. 图片上传压缩、多模态讲解和结果展示。
4. 浏览器语音识别、后端 ASR 兜底、豆包 TTS 和浏览器语音播报。

`frontend-vue/src/components/DigitalHumanPanel.vue` 负责数字人状态呈现，包括待机、聆听、生成、讲解和异常状态的头像、口型和进度动效。

`frontend-vue/src/components/AdminView.vue` 负责管理后台，包括知识库、景点、数字人配置、问答记录、行为样本和运营看板。管理端写操作必须携带 `X-Admin-Token`。

## 11. 稳定性设计

1. 大模型 API 配置缺失时返回明确提示。
2. 大模型调用失败或超时时切换本地规则兜底。
3. 后端所有入口捕获异常并返回 JSON 错误。
4. 问题长度限制为 500 字。
5. 图片上传前端限制 4MB。
6. SQLite 数据自动初始化，降低部署失败概率。
