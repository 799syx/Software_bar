# 评测标准与技术选型说明

## 1. 核心 AI 能力

本项目明确使用至少 1 个多模态大模型作为核心 AI 能力支撑，默认采用 API 服务方式接入：

| 能力 | 当前选择 | 用途 |
| --- | --- | --- |
| 多模态大模型 | 阿里云百炼 DashScope `qwen3-vl-plus` API | 文字问答、景区图片识别、导览讲解生成 |
| 低延迟备选 | `qwen3-vl-flash` API | 现场演示时降低响应时间 |
| 本地知识库 | SQLite 景区知识库 | 提供景点、路线、服务、票务、交通、安全等事实依据 |
| RAG 检索 | 关键词 + ngram + 余弦相似度混合检索，后续可升级向量检索 | 控制事实性回答，减少模型编造 |
| 规则兜底 | 本地模板与意图识别 | 大模型超时或不可用时保证系统稳定 |

也可替换为其他支持图片输入的 OpenAI 兼容多模态 API，例如 Qwen2.5-VL、InternVL、LLaVA、MiniCPM-V 或自部署视觉语言模型。DeepSeek 文字模型只能作为文本问答备用，不作为多模态核心能力证明。

## 2. 需要准备的 API

必需：

```text
DASHSCOPE_API_KEY
模型：qwen3-vl-plus
Base URL：https://dashscope.aliyuncs.com/compatible-mode/v1
```

可选：

```text
qwen3-vl-flash：低延迟演示备用。
DeepSeek API Key：文字问答备用。
TTS/ASR API：增强语音自然度时使用。
```

## 3. 准确率评估口径

题目要求“对于景区问题的事实性回答准确率不低于 90%”。本项目建议将评估主体明确为当前演示景区“灵山胜境”的官方资料包和本地知识库。

评估方式：

1. 根据本地知识库整理标准测试集。
2. 每个测试问题配标准答案和可接受同义表达。
3. 系统回答必须与知识库事实一致，不得编造未入库信息。
4. 答案完整命中关键事实即判定正确。
5. 回答中如果资料不足，应明确说明“暂未查询到准确资料”，不能硬编。

如果使用两个景区数据集，则每个景区都需要独立知识库和测试集。比赛阶段建议先把一个景区数据集做扎实。

## 4. 标准测试集建议

| 类别 | 示例问题 | 关键事实 |
| --- | --- | --- |
| 开放时间 | 景区几点开放？ | 以景区公告为准，演出和场馆开放时间需按资料说明 |
| 票务政策 | 门票多少钱？ | 成人票 210 元，半价票 105 元，网购门票加观光车联票 225 元 |
| 交通停车 | 观光车多少钱？ | 单独购票 40 元/人，适合体力有限游客 |
| 景点讲解 | 灵山大佛有多高？ | 通高 88 米，含台基 101.5 米，用铜量约 725 吨 |
| 亲子路线 | 适合孩子玩的景点有哪些？ | 九龙灌浴、佛手广场、百子戏弥勒、梵宫、五印坛城 |
| 历史文化 | 喜欢历史文化怎么逛？ | 灵山大照壁、祥符禅寺、灵山大佛、梵宫、五印坛城 |
| 拍照打卡 | 哪里适合拍照？ | 灵山大照壁、九龙灌浴、灵山大佛、五印坛城、曼飞龙塔 |
| 安全服务 | 迷路或身体不适怎么办？ | 前往游客服务中心或联系工作人员 |
| 无障碍服务 | 行动不便游客怎么办？ | 补充轮椅租借、无障碍路线和服务中心说明 |
| GPS 场景 | 定位不准怎么办？ | 手动描述位置、上传现场照片、前往开阔处重试 |

建议准备 30 到 50 条测试问题，覆盖同义问法，例如“几点开门”“开放时间”“晚上能去吗”等。

## 5. 自然度评估说明

自然度主要由演示视频评估，重点包括口型同步、语音合成、表情配合和交互流畅度。

当前实现：

1. 使用原创小僧童 PNG 形象作为 2D 数字人主视觉。
2. 语音播报时通过音量条、发光提示和讲解状态动效表现“正在讲解”。
3. 根据状态切换待机、聆听、思考、讲解和异常提示。
4. 优先使用豆包/火山引擎 TTS，未配置时回退 Microsoft/Edge 中文 Natural 神经语音，降低浏览器默认 TTS 的机械感。
5. 回答文本控制在适合语音播报的长度，避免过长导致体验拖沓。

后续增强：

1. 使用 ParaTTS 或同类开源 TTS 生成更自然的中文讲解音频。
2. 使用 Whisper 或 faster-whisper 做语音识别，替代浏览器能力。
3. 使用 TTS 音素、能量曲线或 viseme 时间戳驱动嘴型。
4. 使用 Live2D、SadTalker、MuseTalk 或第三方 2D 数字人 SDK 展示形象。

题目允许“开源 2D 数字人驱动方案或相关 SDK”。如果使用第三方平台数字人 API，也可以作为展示方案，但需在 PPT 中说明调用方式和项目边界。

## 6. 响应延迟与稳定性

目标：普通语音问答延迟控制在 5 秒以内。

实现策略：

1. `SCENIC_LLM_TIMEOUT=5`，避免长时间等待模型。
2. 常见问题先走本地知识库检索和规则兜底。
3. 大模型接口超时或异常时自动降级，不让页面卡死。
4. 图片识别属于多模态重任务，可在演示中单独展示，不与普通语音问答混在同一链路。
5. 关键演示问题提前加入知识库和测试集，确保事实性回答稳定。
6. 演示前先进行 1-2 次问答预热，确认 API Key 和网络可用。

稳定性评估重点：

1. 系统不崩溃。
2. 接口异常能返回可理解提示。
3. 大模型不可用时仍能展示本地知识库回答。
4. 管理端编辑后数据能正常保存和再次查询。

## 7. 复杂现实场景扩展

可选增强方向：

1. GPS 定位：游客授权后根据当前位置推荐最近景点、卫生间、出口和服务中心。
2. 定位困难：GPS 信号弱时允许游客上传现场照片，由多模态模型识别场景并给出可能位置。
3. 室内定位：景区平面图手动标点、二维码点位、蓝牙信标或 Wi-Fi 指纹。
4. 拥挤避让：后台维护景点拥挤度，路线推荐时避开高峰点位。
5. 离线兜底：景区弱网情况下使用本地知识库和规则问答，保证基础服务可用。
